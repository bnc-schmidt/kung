# Kung Server

One small Node server (no dependencies, no Docker) for:

- **Live run sync**: Kung clients on the same Hypixel server share the revealed map, room
  states, secrets and deaths. Memory only, expires after `KUNG_LIVE_ROOM_SYNC_TTL_MS`.
- **Hypixel proxy** for the CA50/C50 calculator. The Hypixel key stays on the server, never in
  a jar. Each player is cached for `KUNG_PROFILE_CACHE_MS`, each client IP and each signed-in
  player get a few lookups per 5 minutes (see Auth).
- Optional shared room data, stored in `KUNG_ROOM_DATA_PATH`. Everyone reads it, only the
  listed writers add to it.

## Endpoints

| Endpoint | Purpose |
| --- | --- |
| `GET /health` | `{"ok": true}`, no auth |
| `POST /auth/challenge` | new sign-in challenge, no auth |
| `POST /auth/login` | trade a joined challenge for a session, no auth |
| `GET /runs/live?runKey=…` | live run snapshot from the other clients |
| `POST /runs/live/report` | report this client's live run state |
| `GET /hypixel/profiles?uuid=…` | the player's SkyBlock profiles, cut down to what Kung reads (503 without `HYPIXEL_API_KEY`) |
| `GET /hypixel/secrets?uuid=…` | the player's lifetime secrets, `{"success":true,"secrets":N}` (-1 when unknown), for the run's per-player secret counts |
| `GET /rooms` | shared room data |
| `POST /rooms/report` | add a learned room (writers only, see Auth) |

Every other endpoint needs `Authorization: Bearer <session token>`.

## Auth

No shared token and nothing to type. Kung signs in the way vanilla joins a server:

1. `POST /auth/challenge` returns a random challenge, valid for 60 s and single use.
2. The client calls Mojang's `joinServer` with that challenge as server id. Its access token
   only goes to Mojang, never to this server.
3. `POST /auth/login` with `{"name", "challenge"}`. The server asks Mojang's `hasJoined` who
   joined and returns a session token, valid for `KUNG_SESSION_TTL_MS` (default 12 h).

Live run reports and snapshots use the session's player name, so nobody can post as someone
else. Sessions live in memory; a restart just makes clients sign in again.
`KUNG_AUTH_LIMIT_PER_5_MIN` limits sign-in attempts per client IP.

Sign-in is open to every Mojang-verified account, with one session per player: signing in
again replaces the earlier token.

`KUNG_ROOM_WRITER_UUIDS` only gates room uploads (`POST /rooms/report`): comma-separated
Minecraft UUIDs, dashes optional. Unset, it falls back to `KUNG_ALLOWED_UUIDS`. An empty list
(set but blank, or both unset) means nobody can upload (403); every other endpoint stays open
to any signed-in player.

Limits per 5 minutes, per client IP unless noted:

| Variable | Default | Applies to |
| --- | --- | --- |
| `KUNG_AUTH_LIMIT_PER_5_MIN` | 20 | `/auth/challenge`, `/auth/login` |
| `KUNG_PROFILE_LIMIT_PER_5_MIN` | 30 | `/hypixel/profiles` |
| `KUNG_PROFILE_USER_LIMIT_PER_5_MIN` | 30 | `/hypixel/profiles`, per player |
| `KUNG_SECRETS_LIMIT_PER_5_MIN` | 60 | `/hypixel/secrets` |
| `KUNG_SECRETS_USER_LIMIT_PER_5_MIN` | 30 | `/hypixel/secrets`, per player |
| `KUNG_LIVE_REPORT_LIMIT_PER_5_MIN` | 1800 | `POST /runs/live/report`, per player |
| `KUNG_ROOM_REPORT_LIMIT_PER_5_MIN` | 30 | `POST /rooms/report`, per player |

Over a limit the server answers 429. The live report default is 3x what the client sends
(one report per 10 ticks, 600 per 5 minutes), so normal play never trips it.

## Setup on a Debian/Ubuntu LXC

Proxmox: an unprivileged container with `nesting=1` is enough. Everything lives in one folder
that can be anywhere in the container, for example `/root/kung-server` (no spaces in the path).
`install.sh` installs in the folder it sits in:

```text
<folder>/
  kung-room-sync-server.mjs   you upload
  install.sh                  you upload
  .env.example                you upload (optional, a dotfile)
  kung-server.env             config and secrets, created by install.sh (root, mode 600)
  kung-server.service         systemd unit, generated by install.sh and linked into systemd
  data/known-rooms.json       room data
```

1. Install Node.js 18 or newer (LTS from NodeSource), as root:

   ```bash
   apt-get install -y ca-certificates curl gnupg
   install -d -m 755 /etc/apt/keyrings
   curl -fsSL https://deb.nodesource.com/gpgkey/nodesource-repo.gpg.key | gpg --dearmor -o /etc/apt/keyrings/nodesource.gpg
   echo "deb [signed-by=/etc/apt/keyrings/nodesource.gpg] https://deb.nodesource.com/node_24.x nodistro main" > /etc/apt/sources.list.d/nodesource.list
   apt-get update && apt-get install -y nodejs
   ```

2. Upload three files from this repo folder into one folder in the container (WinSCP or any
   other file transfer), for example `/root/kung-server`: `kung-room-sync-server.mjs`,
   `install.sh` and, optionally, `.env.example`. `.env.example` is a dotfile and easy to miss:
   select it explicitly. The unit file is not uploaded, `install.sh` generates it.

3. Open the container's console (for example in the Proxmox web UI: container, Console) and run
   the installer there as root, from inside that folder (or with its full path):

   ```bash
   cd /root/kung-server
   bash install.sh
   ```

4. Fill in the config in the same folder, then restart:

   ```bash
   nano kung-server.env    # KUNG_ROOM_WRITER_UUIDS, optional HYPIXEL_API_KEY
   systemctl restart kung-server
   ```

`install.sh` is safe to run twice:

- It requires Node.js 18 or newer (`command -v node`), generates `kung-server.service` in the
  folder (with that node path and the folder's path) on every run, and creates `data/`.
- It finds an old install through systemd (falling back to `/opt/kung-server`,
  `/etc/kung-server.env`, `/var/lib/kung-server`) and creates `kung-server.env` (copied from the
  old env file; without one it uses `.env.example`, and without that a minimal file with only
  the data path, plus a warning). If the folder is itself the old install location, the new
  file simply replaces the old one in place; nothing inside the folder is ever deleted.
- The old room data is copied, compared byte for byte and only then moved into place. An old
  `host.conf` drop-in is folded into the env file (`KUNG_ROOM_SYNC_HOST`).
- The old service is stopped, the unit linked into systemd, the service started and checked:
  `/health` answers, the unit is active, it has not restarted, and it runs the new file. If
  anything fails, the old unit is put back and the old service started again (rollback);
  nothing is deleted.
- Only then it lists the old files that are left and asks before deleting them (`--yes` skips
  the question). Deletion is per exact file, never recursive:
  - the old `kung-room-sync-server.mjs` (its folder only if it is empty afterwards, so a backup
    next to it survives),
  - the old env file, only if every setting in it is also in the new one (it names the keys
    that differ, never the values),
  - the old room data file, only if it is identical to the new one (its folder only if empty),
  - the set-aside old unit file and `host.conf` (`*.pre-kung-migrate`).
- Old Docker containers are only listed with the commands to remove them, never removed.

It refuses, before changing anything, when the old data file is a symlink or the same file as
the new one, or when the folder or its `data` directory is a symlink or mount point, or when the
folder path has spaces or other special characters. It also stops when the port is still in use
after the old service was stopped (pm2, docker, another unit).

The service runs as root inside the container (the folder lives under `/root`, which no other
user can enter) and can only write to `<folder>/data`. If you move the folder, run `install.sh`
again from the new place: it regenerates the unit and points systemd at it.

## Health check

```bash
curl http://127.0.0.1:8765/health    # {"ok": true}
journalctl -u kung-server -n 20
```

## Updating

Replace `kung-room-sync-server.mjs` in the install folder with the new file, then:

```bash
systemctl restart kung-server
```

Tests (fake Mojang and Hypixel, no network), from the repo root:
`node --test deploy/kung-room-sync/kung-room-sync-server.test.mjs` (naming the file does not
depend on glob support in `node --test`, which older Node versions lack).

## Kung client setup

Nothing to type: `https://kung.bengcoding.org` is the built-in server URL. Live map sync is
still opt-in (`/kung roomsync enable`). The CA50 calculator uses the server when you have no
own Hypixel key. Anyone signs in and reads; a player not on the writers list just has room
uploads refused (403). `/kung roomsync server <url>` overrides the URL; a blank URL means no server.

## Cloudflare Tunnel

The tunnel is the only way in; no router port is opened.

1. Install `cloudflared` from Cloudflare's apt repo (pkg.cloudflare.com).
2. Create a tunnel in Zero Trust, then `cloudflared service install <tunnel-token>`.
3. Public hostname `kung.bengcoding.org` → `http://localhost:8765`.
4. Bind the server to localhost: set `KUNG_ROOM_SYNC_HOST=127.0.0.1` in
   `kung-server.env` in the install folder, then `systemctl restart kung-server`. (An old `host.conf`
   drop-in that did this is moved into the env file by `install.sh`.)
